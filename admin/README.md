# SURD — Admin

Internal admin dashboard, and the home of the shared component library.

---

## Getting started

```bash
cp .env.example .env.local   # set NEXT_PUBLIC_GRAPHQL_ENDPOINT first
npm install
npm run dev          # http://localhost:3000
npm run build        # run before opening a PR
npm run lint
npm run sync:flags   # re-copy country flag SVGs into public/ after an upgrade
```

`NEXT_PUBLIC_GRAPHQL_ENDPOINT` is read at **build** time — it is pinned into
the CSP's `connect-src`, so a production build without it is refused rather
than shipped with a policy that blocks every API call. `npm run dev` warns and
carries on.

### Routes

**Never write a path as a string literal.** Every URL lives in
[`constants/routes.ts`](constants/routes.ts):

```tsx
import { ROUTES } from "@/constants/routes";

<Link href={ROUTES.users.detail(user.id)}>…</Link>;
```

Rename a route there and every link follows; TypeScript catches whatever
doesn't.

| Route                      | What it is                                        |
| -------------------------- | ------------------------------------------------- |
| `/`                        | Redirects to `/login` — the default landing page   |
| `/login`                   | Sign-in step one: email                            |
| `/verify-email`            | Sign-in step two: six-digit code                   |
| `/dashboard`               | Console home                                       |
| `/flexi-wallet`            | Instant-access balances by holder                  |
| `/savings`                 | Target savings plans across every account          |
| `/roi`                     | Interest accrued, paid and clawed back             |
| `/vault`                   | Fixed deposits and locked funds                    |
| `/treasury`                | Safe deployable capital + withdrawal approvals     |
| `/transactions`            | The full ledger (server-paginated)                 |
| `/users`                   | User list                                          |
| `/users/[id]`              | One user — 7 tabs, close-account flow              |
| `/kyc`                     | KYC & Compliance queue                             |
| `/rates`                   | FX rates                                           |
| `/product-configuration`   | Target savings / Fixed deposit / Flexi Wallet      |
| `/admin-accounts`          | Admin users, roles and permissions                 |
| `/content`                 | Copy across mobile, admin and website              |
| `/platform-configuration`  | Platform-wide system keys                          |
| `/audit-logs`              | Every administrative action, filterable            |
| `/components`              | Component gallery (developer reference)            |
| `/foundations`             | Design tokens (developer reference)                |

Open `/components` first. It is the fastest way to see what already exists
before you build something new.

### Naming

**Files and folders are lowercase, hyphen-separated.** Components stay
`PascalCase`; only the filename is kebab-case. Import through the `@/` alias.

```
✅ components/ui/currency-input.tsx  →  export function CurrencyInput()
❌ components/ui/CurrencyInput.tsx
```

## Design tokens

Everything lives in [`app/globals.css`](app/globals.css). Tailwind's stock
values are cleared (`--color-*: initial`), so **only SURD tokens exist** — there
is no `bg-zinc-500`, there is `bg-grey-500`.

- Colour — `surd-blue-50…900`, `grey-10…1000`, plus `green` `aqua` `blue`
  `purple` `pink` `red` `orange` `yellow` (`50…950`)
- Type — `text-display-*`, `text-heading-*`, `text-{2xs…2xl}`,
  `text-paragraph-*`, `text-label-*`
- Effects — `shadow-{xs…2xl}`, `blur-*`, `shadow-ring-*` for focus states

Semantic aliases (`bg-surface`, `text-foreground-muted`, `border-border`,
`bg-primary`…) sit on top and are what application code should normally use.

## The component library

All under `@/components/ui/`.

| Component                                   | Notes                                          |
| ------------------------------------------- | ---------------------------------------------- |
| `Button`                                    | tone × variant × size × shape                  |
| `IconButton`                                | square footprint, `label` required             |
| `SocialButton`                              | six providers, solid / outline / icon-only     |
| `Avatar`, `AvatarGroup`, `AvatarLabel`      | photo, initials or glyph, corner indicators    |
| `Badge`                                     | dot, icons, five tones, three variants         |
| `Checkbox`, `RadioGroup`, `Switch`          | Radix-backed                                   |
| `Field`                                     | label + control + hint/error                   |
| `Input`, `InputShell`                       | the base field and its shared shell            |
| `Select`                                    | Radix select wearing the input shell           |
| `NumberInput`, `PhoneInput`, `CurrencyInput`| composite fields                               |
| `InputAction`                               | in-field text action ("Get OTP", "Max")        |
| `Flag`, `CryptoIcon`                        | country and token artwork                      |

### The four axes

Most components share one vocabulary, so learning it once covers the library:

```tsx
tone     "neutral" | "primary" | "danger" | "warning" | "success"
variant  "solid" | "soft" | "outline" | "ghost"
size     "xs" | "sm" | "md" | "lg" | "xl"
shape    "rounded" | "pill" | "square"
```

```tsx
<Button tone="danger" variant="outline" size="lg" leadingIcon={Delete02Icon}>
  Delete account
</Button>
```

### Variants are lookup tables

Never chain ternaries for styling. Every component declares a record and
derives its union type from it, so adding a tone is one line and the types
follow automatically:

```tsx
const toneStyles: Record<ButtonTone, Record<ButtonVariant, string>> = { … };
export const BUTTON_TONES = ["neutral", "primary", …] as const;
export type ButtonTone = (typeof BUTTON_TONES)[number];
```

The exported `BUTTON_TONES`-style arrays also let the gallery enumerate every
combination, so new variants show up on `/components` for free.

### Inputs share one shell

`InputShell` owns all field styling — surface, border, radius, height, and the
hover / focus / error / disabled transitions. Every field type renders its
contents inside a shell instead of restyling a box, which is why they all line
up and focus identically.

**Hover and focus are CSS states, not props.** The only states you set are:

```tsx
state="default"   // resting
state="error"     // failed validation
state="active"    // deliberately highlighted
disabled          // its own prop
```

Composing a new field type usually means passing `leading` / `trailing` nodes
rather than writing a new component:

```tsx
<Input
  placeholder="100.00"
  trailing={<InputAction onClick={sendOtp}>Get OTP</InputAction>}
/>
```

### Server vs client

Components are server components unless they need state or DOM events.
Anything Radix-backed (`Checkbox`, `Select`, `Switch`, `RadioGroup`) and
anything taking a callback (`AvatarGroup`'s `onAdd`, `NumberInput`'s stepper)
is marked `"use client"`. A server component **cannot** pass a function prop —
if you hit that, wrap the usage in a small client component.

### Icons

```tsx
import { Home01Icon } from "@hugeicons/core-free-icons";
import { Icon } from "@/components/ui/icon";

<Icon icon={Home01Icon} size="md" className="text-primary" />;
```

Icons are passed as **data, not markup**, so the parent controls their size.
That is why `Button` takes `leadingIcon={PlusSignIcon}` rather than a rendered
element.

Note `ArrowRight01Icon` is a chevron; `ArrowRight02Icon` is a true arrow.

### Flags

```tsx
<Flag code="NG" />
<Flag code="US" shape="circle" size="lg" />
```

ISO 3166-1 alpha-2, case-insensitive. The SVGs are served from `public/flags/`
as static files, so a page downloads only the flags it renders instead of
bundling all 265. Re-run `npm run sync:flags` after upgrading the package.

### Crypto icons

```tsx
<CryptoIcon symbol="BTC" size="lg" />
```

`@web3icons/react` ships ~1,800 tokens; importing them all would dominate the
bundle, so `crypto-icon.tsx` keeps a **curated registry**. To add a currency,
import its `Token<SYMBOL>` component and add one line to `registry`.

## The building blocks

Four components carry most of the console. Learn these and a new page is
mostly assembly.

### DataTable

Columns are data, so a row is never hand-written twice:

```tsx
const columns: Column<Rate>[] = [
  { id: "pair", header: "Currency Pair", cell: (rate) => <Pair {...rate} /> },
  { id: "value", header: "Value", cell: (rate) => rate.value, align: "right" },
];

<DataTable data={rates} columns={columns} getRowId={(r) => r.id} />;
```

**Pagination, three ways:**

| Need                        | Prop                                              |
| --------------------------- | ------------------------------------------------- |
| Client-side (default)       | omit `pagination` — pass the whole array           |
| Server-side                 | `pagination={{ mode: "server", page, pageSize, totalItems, onPageChange }}` |
| None                        | `pagination={false}`                               |

Tables always scroll inside their own container, so the page never scrolls
sideways. Set `minWidth` to stop columns collapsing.

[`/transactions`](<app/(dashboard)/transactions/page.tsx>) is the worked
example of server mode — it owns `page` and slices the data itself. Every other
table uses the default client mode. Swapping that page's `useMemo` for a fetch
keyed on `page` is the only change needed to go live.

### Dialog

One component covers both modal shapes. `tone` is the whole difference:

```tsx
{/* Form dialog — icon header, your fields, Cancel / confirm footer */}
<Dialog control={editRate} title="Edit Rate" icon={PercentIcon}
        confirmLabel="Save changes" onConfirm={save}>
  <Field label="Rate"><Input … /></Field>
</Dialog>

{/* Confirmation — pass a tone and the badge, centring and button colour
    come with it */}
<Dialog control={closeAccount} tone="danger"
        title="Are you sure you want to close this user account?"
        description="Closing this account will permanently disable access."
        confirmLabel="Yes, close" onConfirm={handleClose} />
```

Tones: `form` (default), `info`, `success`, `warning`, `danger`. Omit
`onConfirm` on a confirmation tone and it becomes a single-button
acknowledgement.

### Drawer

Same Radix primitive, slides in from an edge. Reach for it over a dialog when
the content is long or the user needs the page behind it — record detail,
filter builders, activity feeds.

```tsx
<Drawer control={detail} title="Transaction detail" side="right" width="lg"
        footer={<Button block>Approve</Button>}>
  …
</Drawer>
```

### Dropdown

```tsx
{/* single choice */}
<Dropdown options={STATUSES} value={status} onChange={setStatus} />

{/* many choices, with an All row and optional search */}
<MultiDropdown options={ADMINS} value={admins} onChange={setAdmins}
               label="All admins" searchable />

{/* the applied-filter pill */}
<FilterChip label="2 Modules" onRemove={() => setModules([])} />
```

An empty selection and a full one both mean "no filter" to the caller.

### Hooks

`useDisclosure<T>()` owns open state **and** the payload, so a row can open a
dialog and hand it the record in one call:

```tsx
const editRate = useDisclosure<Rate>();

<button onClick={() => editRate.open(rate)}>Edit</button>
<EditRateDialog control={editRate} />   // reads editRate.data
```

`usePagination()` returns page state plus the `1 2 3 … 9 10` number list.
`useSidebarCollapsed()` persists the rail preference.

`useToast()` raises a transient confirmation; the viewport is mounted by
`DashboardShell`, so any page below can call it.

## Application shell

### Auth pages — `app/(auth)/`

A route group, so `/login` and `/verify-email` share
[`AuthShell`](components/auth/auth-shell.tsx) — the topbar plus the split card —
without nesting a segment in the URL.

The brand panel's diagonal ribbon is **CSS, not an exported image** (the
`brand-ribbon` utility in globals.css). It stays sharp at any size and
re-colours from the palette.

`OtpInput` is controlled by a single string rather than six pieces of state,
and handles what people expect from these fields: typing advances, backspace on
an empty box steps back, arrow keys move, and pasting a full code fills every
box at once.

### Dashboard — `app/(dashboard)/`

[`DashboardShell`](components/dashboard/dashboard-shell.tsx) owns two
independent pieces of navigation state:

- **Collapsed rail** (`lg` and up) — persisted via
  [`useSidebarCollapsed`](lib/use-sidebar-collapsed.ts). `localStorage` is an
  external store, so it is read with `useSyncExternalStore`, not copied into
  state inside an effect. That gives a correct server snapshot with no
  hydration mismatch and keeps tabs in sync.
- **Drawer** (below `lg`) — a Radix dialog, so focus trapping and scroll
  locking come for free.

Both render the same [`SidebarNav`](components/dashboard/sidebar-nav.tsx), so
there is only ever one list to maintain. Navigation lives in
[`content/navigation.ts`](content/navigation.ts) — add an entry there and it
appears in both.

### The rotating gradient border

The active sidebar item has an animated ring, defined as the `rotating-border`
utility in [`app/globals.css`](app/globals.css):

```css
@property --border-angle {
  syntax: "<angle>";
  initial-value: 0deg;
  inherits: false;
}
```

A conic gradient is painted into the *border box* while a flat fill covers the
*padding box*, so only the ring shows the gradient. **The `@property`
declaration is what makes it work** — without registering the custom property
the browser cannot interpolate an angle, and the ring would jump instead of
rotating.

Set `--rotating-border-fill` to match whatever sits behind the element.

## Loading states

- [`app/loading.tsx`](app/loading.tsx) — root fallback, a centred spinner
- [`app/(dashboard)/loading.tsx`](app/\(dashboard\)/loading.tsx) — mirrors the
  real page's block structure (banner, stat row, panels) so nothing shifts when
  content arrives. The shell is already painted by the layout, so this only
  stands in for the workspace.

## Adding a component

1. Create `components/ui/<kebab-case-name>.tsx`.
2. Reuse the shared vocabulary — `tone`, `variant`, `size`, `shape` — rather
   than inventing new prop names for the same ideas.
3. Declare style tables as `Record<Union, string>` and derive the union from an
   exported `as const` array.
4. Accept `className` and merge it with `cn()` so callers can adjust spacing
   without a wrapper.
5. Type props from the element you render:
   ```tsx
   type BadgeProps = React.ComponentProps<"span"> & { tone?: BadgeTone };
   ```
6. Add it to `/components` so it is visible to everyone.

Keep files short. If a component passes ~150 lines, split it.

## Data, sessions and access

The API layer, the session clocks and the permission gates are documented in
**[api/README.md](api/README.md)**. The short version:

- `useAdminUsers({ page, status })` — every endpoint is a hook, every variable
  is passed as `input`, every failure arrives as an `APIError`.
- Sessions expire **8 hours** after sign-in and **15 minutes** after the last
  sign of a person. The idle clock is driven by interaction, not by network
  traffic — a tab refetching on focus does not count as someone being there.
  A dialog gives a minute's notice before the end.
- A 401 clears the token, empties the query cache and redirects to `/login`
  with the reason and the path to return to.
- `<Can do={Permission.TreasuryMove}>` hides a control;
  `<RequirePermission need={...}>` gates a page; the sidebar drops what the
  signed-in admin cannot reach.
